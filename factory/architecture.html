System atlas

The core ticket path, control-plane safeguards, manager, operator surfaces, bounded evidence, codebase history, and learning loop. Repo-specific commands and limits come from layered configuration; SHA-bound approval evidence, green CI, current main, and no human veto remain merge preconditions.

Diagram B — ticket lifecycle

One ticket, start to handoff: triage, configured worker and gate attempts, configured review rounds, then the merge stage or escalation; the configured manager can retry, rewrite, split, route, fix, or close escalated work.

factory/gate.py:101–188 · factory/config.py:88–98

Deterministic gate

  • fixed conflict-marker and leak scans surround every configured [[gate.check]]
  • checks run in declaration order with a configured timeout
  • exclusive checks serialize under the host lock
  • the Markdown report becomes worker, reviewer, dashboard, and learning evidence

factory/dispatch.py:948–981 · 1118–1384 · 1442–1646 · factory/manage.py:461–585

Orchestration and merge

  • sync, serialized landing, review intake, and the configured manager pass run before new claims
  • concurrency, worker attempts, wall-clock budget, and review rounds are configured
  • SHA-bound, approved, green, current PRs without a human veto land one per pass
  • failed gates, exhausted reviews, and budget overruns route to ready-for-human
  • the manager frontier re-escalates red, stale, or late-feedback PRs and can require final approval

factory/dispatch.py:50–62 · 562–594 · 1443–1579

Local state and evidence

  • wt-<n>/ holds the branch, prompt, handoff, and gate report
  • locks/<n>.lock survives worktree cleanup; locks/merge.lock serializes landing
  • logs/, events.jsonl, PR bodies, and review findings remain inspectable
  • pipeline runtime state is gitignored beneath .factory/

factory/dashboard.py:864–1019 · 1167–1228 · factory/lifecycle.py:1–6

Operator surface

  • the dashboard combines GitHub, worktree, lifecycle-ledger, systemd, journal, and gate state
  • /api/act is the explicit human write path for issue and PR decisions
  • the citation-gated briefing and Q&A advisor is read-only
  • the same local server publishes Dashboard, Codebase, and Atlas

factory/codebase.py:478–569 · 704–831 · factory/dashboard.py:1036–1064

Codebase history

  • Graphify extracts commit-pinned structure from local Git objects without switching revisions
  • snapshots preserve file identities across renames and publish atomically to .factory/codebase/
  • the dashboard monitor refreshes local refs every 30 seconds and retains the last good map
  • coverage limits and omissions stay visible instead of becoming inferred relationships
