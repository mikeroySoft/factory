# Review: #79 B2 — source-versioned PR feedback

## Required fixes

### R1. Default full-snapshot GraphQL read now fails closed on any `errors` entry — regression for existing consumers
`factory/dashboard.py:220-222`: `if value.get("errors"): raise RuntimeError("GitHub query was incomplete")` applies to the *default* snapshot query too, not only the feedback queries. Before this diff `github()` returned `value["data"]` unconditionally. GitHub GraphQL routinely returns partial `data` plus `errors` (e.g. unreachable/renamed `{UPSTREAM}` repository, a single field permission error, sub-resource rate limit). Trigger: any such partial response. Impact: `snapshot()` catches at `dashboard.py:828-829`, so **all** issues/PRs vanish from the full snapshot and dashboard, where previously the partial data rendered. Violates issue "Preserve … current snapshot fields for their existing consumers" and "Preserve full-snapshot cadence and existing ticket/PR fields." Fix: keep the pre-diff behavior for the default query; apply the fail-closed check only when `query is not None` (feedback detail reads), or let `feedback.collect` treat `errors` as a source gap.

### R2. Repository native ID is fetched but never wired through; failed initial head read then discards all review/thread evidence
- `factory/dashboard.py:122` adds `repository{ id … }` to `GRAPHQL`, and `dashboard.py:812` declares `repo: dict = {}`, but nothing ever assigns `repo` from `data["repository"]`. `dashboard.py:889` therefore always passes `repository={"id": None, …}`.
- `factory/feedback.py:190-192`: `item()` drops every item with `identity_missing` when `repository['id']` is None. The only thing that populates it in the dashboard path is the initial `HEAD_QUERY` (`feedback.py:162`). Trigger: initial head read times out / 5xx / returns `identity_conflict` while `REVIEW_QUERY`/`THREAD_QUERY` succeed. Impact: successfully read reviews and thread comments are all discarded as `identity_missing`, and (because `success('reviews')` ran at `feedback.py:274`) coverage reports `partial`, not the actual loss. Violates issue: "One failed source must not discard usable independent sources" and "Use the GitHub native repository ID."
- Secondary: for `collect_details=False` (closed/merged PRs, `dashboard.py:896`) `repository.id` is always null and `observation_id` (`feedback.py:439`) is computed over a null repo ID although the snapshot holds the real one. Issue exit gate 1 requires native IDs retained.

Fix: assign `repo = data["repository"]` in `snapshot()` next to `dashboard.py:816` and pass `repo.get("id")`. Tests in `tests/test_feedback.py` always supply `REPO["id"]`, so this wiring gap is untested; `tests/test_factory.py:2440-2446` should assert `feedback["repository"]["id"] == REPO["id"]` for both the open and the non-collected PRs.

- `factory/dashboard.py:875-879` runs three `git` subprocesses in the *installed package directory* on every full snapshot (15 s cache). For a non-git install location (`uv tool`, site-packages) behavior depends on `sh()` failure semantics, which are outside the diff — `[INFERENCE]` if `sh` raises on nonzero exit, `snapshot()` crashes. `tests/test_factory.py:2457-2473` only exercise a temp *git* repo. - `factory/dashboard.py:896` `collect_details=raw.get("state") == "OPEN"` narrows the issue's "when a PR is present … return the schema-1 object with explicit unavailable/partial coverage" to open PRs only. Documented (README/CHANGELOG) and schema-compliant, but it is a scope decision not visible in the issue comments; name it in the handoff so the #15 owner knows merged/closed PRs carry `not_collected` rather than historical evidence.

- `factory/feedback.py:251-253`: on `source_identity_conflict` the previous item is removed but `counts[source]` is not decremented; `item_limit` can trigger one item early. Cosmetic.
- `factory/briefing.py:209`, `:272-273`, `:232-235` and `factory/dashboard.html:1260`, `:1263-1266`, `:1089-1094`: relabeling of pre-existing sources/facts ("Legacy …", "factory-approved label present", gate line) and removal of the `PASS/FAIL` chip classes on legacy verdicts are not required by the issue ("`sources_for` only, preserving existing … conventions"; "existing `tabReview` … presentation only"). Those helper semantics are outside the diff — `[INFERENCE]`. Exit gate 5's browser smoke is the only evidence; it is not in this packet.
