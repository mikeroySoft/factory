Requesting changes for one important issue: on Factory's documented install paths, `producers.reader` always reports the engine build as unknown, even though a build commit is recorded on disk. That leaves the issue's first acceptance criterion unmet wherever the engine is actually installed.

**Spec (issue #87)**
- **The fix only works from a source checkout.** `reader_build()` (`factory/evidence.py:374-396`) finds a revision only through `git -C <package dir>`. The README's install methods are `uv tool install git+…@stable|@main|<tag>`, pipx, and `pip install --user`. All of them put the package in site-packages, which isn't a git checkout, so the result is always `{"revision": null, "verified": false}`.
  - **The revision is available.** The Factory install on this host has a `factory-0.4.6.dist-info/direct_url.json` with `vcs_info.commit_id` (`71ed49cf…`). Its `RECORD` holds a sha256 for `factory/evidence.py`, which can detect a locally modified install, playing the role of the clean-checkout test in the diff.
  - **Why it blocks.** Acceptance criterion 1 asks the output to identify a verifiable build revision. Criterion 2 speaks of the "installed build identity" and allows "unknown" only when provenance is unavailable. Here it is available.
  - **The test misses it.** The "verified" case (`tests/test_evidence.py:290-306`) loads the engine from a git checkout via `PYTHONPATH`, which isn't an installed build.
  - **Smallest fix:** keep the git-checkout branch, and also read `direct_url.json` and `RECORD` from the package's own dist-info. That stays inside `reader_build()`, with no new abstraction.
- **What does meet the brief:**
  - The engine identity sits under its own `producers.reader` key, apart from `scope.repository`/`scope.root`.
  - It never falls back to the factory version string or the `--root` HEAD.
  - The git calls set `GIT_OPTIONAL_LOCKS=0`, so they don't write to the index.
  - Output stays within the existing bounds.
  - The test drives the real JSON CLI for both cases, under the write guard.

**Standards (nits)**
- `evidence_schema: 1, runtime_schema: 1` now appear both in `reader` (`factory/evidence.py:395-396`) and next to it in `producers` (`factory/evidence.py:420`), so the two copies can drift apart.
- The README's capabilities contract (`README.md:1161`) and the `CHANGELOG.md` Unreleased section don't mention the new `producers.reader` field. `docs/autonomy-execution-plan.md:693` gives those files to an integrator, so this doesn't block.
- `tests/test_evidence.py:306` compares against `self.head`, which is the `topic` commit, while the selected root's HEAD is `self.main`. The equality check on the line before already proves the point, so this line is redundant and would not catch a fallback to the `--root` HEAD.
