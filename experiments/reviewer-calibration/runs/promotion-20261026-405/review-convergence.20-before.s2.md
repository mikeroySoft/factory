**The important defect.** FIX ends with a plain `git push` (`review.diff:159`). That push only works when the local branch is still ahead of the remote one in a straight line.
- **Trigger:** the shipped `conflict` profile tells the worker to rebase onto main. Also, after a "gate failed after rebase" escalation, the kept worktree is already rebased but not pushed (`snapshot/factory/dispatch.py:722-731`). In both cases the local branch has rewritten history.
- **Impact:** the push is always rejected. The error is swallowed as a mechanism failure, so the work that passed the gate is never reviewed, and the only trace on GitHub is the earlier escalation comment.
- **Follow-on:** a PR escalated for a rebase conflict keeps its `factory-approved` label. On the next merge pass, `refresh_pr_branch` force-pushes those same FIX commits with no fresh review. That breaks the README promise at `review.diff:21` that only a fresh APPROVE restores approval.
- **Fix:** use `--force-with-lease`, as `refresh_pr_branch` already does. No new abstraction is needed.
