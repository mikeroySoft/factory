## 0.4.6 — 2026-10-23

- Gate checks replace invalid UTF-8 bytes in captured output instead of crashing before the gate report is written (#361).

- Structured schema-1 decision records now capture triage, initiative binding, scheduler admission, worker selection, and claim alternatives, inputs, rationale, causes, actor, and model cost in the rotating journal. `factory explain N [--json] [--since ISO]` projects those rows plus legacy audit events into a bounded decision graph with cross-ticket edges and coverage gaps (#356).
- Post-claim schema-1 decision records now cover every gate run, reviewer verdict, manager action, merge/refresh choice, wontfix terminal, escalation, learning pass, and CURATE proposal. `factory explain --json` groups review retries into costed loops, totals ticket cost, links findings and cross-ticket evidence, and reports a stage-aware frontier through merge or wontfix. Historical dependency edges override the frontier only during triage or binding, so later stages report their current wait even without an admission record. Retry loops end before the next review, retry source, or escalation, keeping their nodes and costs disjoint and excluding later manager decisions. Coverage gaps remain limited to the original five part-1 stages rather than optional post-claim branches. Conflict and manager requeues return the frontier to the gate. Reviewer findings are collected from every `Required fixes` section, including suffixed headings; empty `None` sections add no finding, explicit file:line references are preserved, and other findings link to the published review comment or existing PR (#357).


- Automatic release PRs now keep public installation guidance current (#351): `factory release` updates and stages the version file, `CHANGELOG.md`, the fixed-version install pins in `README.md` and `docs/index.html`, the project page's latest-release date, and a new page history entry built from that version's changelog notes. Every expected documentation spot must match exactly once or the release is refused.

## 0.4.5 — 2026-10-23

- Opt-in worker profiles can select a stable profile name from a separate ticket label with `when = { label = "..." }`, apply profile-local environment variables, and record a pinned worker version. The Prime Agent pilot uses these fields to isolate telemetry-disabled state beneath the target repository's `.factory/`, retain OMP-compatible transcripts, and leave every non-pilot worker unchanged (#332).

- `factory watch` no longer reports repeated `ci_failed` escalations as engine defects (#340): `ci_failed` records a ticket PR's failed checks, which the merge stage already withdraws from approval and escalates as a ticket outcome.

- A transient GitHub issue-claim failure no longer aborts the dispatcher pass or strands the ticket (#327): the unmodified, unassigned ticket is retried next pass after a `claim-failed` journal row and lifecycle wait. Failed checked commands log only the last 2,000 characters of stderr after redacting token-shaped strings across the complete stderr first.
- `factory watch` now files a `bug,host,needs-triage` issue when `worker_exit:*`, `triage_endpoint_*`, or `github_command_failed` persists uninterrupted for `[watch].host_failure_minutes` (default 60), while shorter blips remain ignored (#336). A gap between failures longer than that threshold starts a new streak, since idle successes may leave no journal row. The host-condition fingerprint is shared across installs, its issue carries the failure rows, and a later successful pass clears the streak so normal stale-close behavior closes the filing.

- Dashboard startup now reports actionable, secret-free remedies when `.factory` or its workspace access key is unsafe, and `factory doctor` checks the same safety rules before the dashboard service enters a restart loop (#328).

- Jev reviewer-coverage experiment (#141): 33 no-retry `jev-latest` calls over the frozen 11-packet reviewer corpus asked one Noul per acceptance-criterion/file pair and one per whole diff. Resolved model `jev-1.14.0` flagged none of the primary defects the retained reviewer baseline missed and averaged 1.333 false flags per clean `after` packet, so the fixed decision is `no-change`; raw requests/responses, split/repeat noise, cost/latency, pre-call mapping, and the schema-1 record are retained under `experiments/jev-review-coverage/`.

- Optional triage endpoint recovery (#335): host `[triage].service` makes `factory install` add a two-minute `GET <base>/models` liveness timer. Three consecutive failures restart the systemd user service, with a shared 15-minute cooldown across repositories; 503 `Loading model` remains healthy. Probe failures and restarts are lifecycle-journaled, while an unset service remains report-only and installs no probe timer. `factory doctor` reports the probe state.
- Factory now exposes each repository's last successful `triage`, `dispatch`, and `watch` pass for District alerting (#337): successful non-dry-run passes atomically update `.factory/stage-success.json`; `factory stats --stages`, evidence `observe`/`inspect`, and `factory doctor` report the same timestamps without a GitHub read.

## 0.4.4 — 2026-10-23

- Worker and reviewer capabilities are explicit instead of tied to an `omp` executable name (#334): `[workers.<label>].transcript = "omp-session"` captures compatible JSONL for token usage, scoring and learning, while `[review].json_mode = true` enables OMP-compatible JSON review parsing. Commands named `omp` retain both defaults, undeclared workers still report usage as `n/a (not reported)`, and `factory stats --by-worker` now includes reported worker token totals.

- `factory watch` no longer reports repeated `review_revise` escalations as engine defects (#324): every `review_revise` is a ticket outcome, whether bounded review rounds are exhausted, review after a manager `FIX` still requests changes, or fresh review after a merge-stage refresh/rebase requests changes.

- A refresh conflict onto moved `main` no longer escalates (#295): the merge stage withdraws `factory-approved`, journals a `conflict-requeue` row (PR, head, conflicting files, round) and releases the ticket, removing `ready-for-human` and adding `ready-for-agent` (including after a manager `FIX`), so the next claim runs a worker in the same worktree on the same `agent/<n>` branch with a brief to rebase onto current `origin/main`, resolve the conflicts, keep the approved intent and not widen scope; the normal gate, lease push, independent review and round limits follow, and only a fresh approval restores the label. It still escalates as `refresh_conflict`, with the conflicting files in the packet, for a protected path without `factory-protected-override`, after `review_rounds` conflict requeues, or when the ticket is not open. A manager `FIX` whose kept worktree is ahead of the PR head with a head a journaled worker attempt produced (#264) pushes it with a lease on the recorded PR head and goes on; any other head escalates as `refresh_head`, a refused lease as `lease_refused`.
- Automatic releases publish the GitHub Release (#320): after pushing the `v*` tag and `stable`, `factory release` runs `gh release create <tag> --verify-tag --latest` titled with the tag, with that version's `CHANGELOG.md` section as notes. A Release that already exists is left alone; a `gh` failure is journaled as a `release` row with outcome `publish_failed` and retried at the start of the next pass without rolling back the tag. v0.4.2 had stayed behind v0.4.1 as GitHub's latest until it was published by hand.

## 0.4.2 — 2026-10-18

- The dispatcher advances an open release PR at the start of a pass, before landing a ticket, and opens new release PRs only at the end of a pass: a release PR opened at the end of one pass used to turn conflicting on `CHANGELOG.md` as soon as the next pass landed a ticket, and was closed and rebuilt forever.
- A worker that passes the gate, commits nothing and writes its handoff (its ticket was already fixed or a duplicate) now escalates as `no_change` with "worker committed nothing over <main>; read the handoff", not `pr_unpublished`, and `factory watch` never files repeated `no_change` escalations as a factory defect (#300: #278, #279 and #291 were watch-filed tickets already fixed on main). A worker that commits nothing and writes no handoff (it crashed or exited early) still escalates as `pr_unpublished`, which watch keeps counting. The workspace capacity test now waits for request admission before probing the only client slot, so its probe cannot make the server reject the connection under CI scheduling.
- Generated units quote `[install].env` / `dispatch_env` values that contain spaces or other systemd-significant characters: an unquoted `Environment=UV_EXCLUDE_NEWER=24 hours` set `UV_EXCLUDE_NEWER=24`, which made every `uv` command in the dispatcher and gate exit with a usage error.
- Runtime projection no longer reports `identity_conflict` for the dispatcher's ticket scope (#293): that scope advances `attempt` and `review_round` in place so worker, gate and review children inherit them, so every live journal with a retried or reviewed ticket tripped the check. Only fields fixed at scope creation (`dispatcher_run_id`, `root_execution_id`, `execution_id`, `parent_execution_id`, `ticket`, `stage`) must agree across an execution's rows; the projected execution reports its latest `attempt`/`review_round`.
- Managers may use `AUTHORIZE` with an auditable justification and worker guidance to permit a required edit to an existing `[gate].add_only_paths` file, whether or not a PR exists. Factory adds `factory-add-only-override` and requeues the ticket through the normal gate and independent review. The label permits in-place edits only: deleting, renaming or changing the mode of an add-only file still fails, and a path matching both a protected and an add-only glob is protected (an additive change to it no longer passes without a label). Fully protected paths such as `.factory.toml` still require the human-only `factory-protected-override`.
- Automatic patch releases ratchet quality from the latest reachable semver tag: `factory release` measures merged-ticket human and first-pass rates, requires enough tickets, new CI-green `main` commits, a no-worse recorded bar, and the release-tier gate, then converges in up to three dispatcher passes by opening a factory-owned release PR, squash-merging it after its required `gate` check passes, and annotating the merged commit while advancing `stable`; `[release].auto` runs it after successful dispatcher passes and `--dry-run` reports the remote-derived state and next action without writes.
- Triage no longer re-triages a `wontfix-proposal` every pass: the decision now swaps `needs-triage` for the `wontfix-proposal` label (as manager `CLOSE` already does) instead of commenting and leaving `needs-triage`, which re-ran the model and posted a fresh proposal comment on each 10-minute pass (rocm-cli #57 collected 211). The issue stays open; a human closes it or puts `needs-triage` back.
- `factory watch` files one issue per defect, not per place it showed: the fingerprint is now kind + reason/unit/source, so a reason seen in several lifecycle stages (`FileNotFoundError: 'omp'` in `worker`, `ticket` and `dispatcher`: #256/#257/#260) or several reader codes from one journal (`missing_enter`, `identity_conflict`) make one `bug` whose title lists the stages or codes. Host conditions the dispatcher already retries or escalates are never filed: `worker_exit:*`, `triage_endpoint_*`, `github_command_failed`. Existing open watch issues keep their old fingerprint, so a still-present signal refiles once under the new one.
- Upstream sync through the ordinary pipeline (#151): `sync_pass` no longer pushes `main`. It stages the candidate in a detached worktree (upstream tip merged `--no-ff`, or the newest conflict-free prefix when the tip conflicts), runs the host gate on a clean merge (that dispatcher-only run keeps `--skip leak-scan --protected-override`: nothing in it is worker-written), files one `upstream sync:` issue labelled `ready-for-agent` whose body carries the exact conflict list or gate report, and hands the candidate to `agent/<n>` (`attempt` row with `attempt: 0`, `upstream-sync` row with the tip and staged head; lifecycle stage `upstream-sync`, reason `upstream_staged`). The ticket then runs the normal worker → gate → review → PR → CI → merge stages: a staged candidate whose gate passed skips the worker, a failed one is repaired within `max_attempts`/`budget_min` with the gate rerun after every attempt, `worker_round` rejects a passing gate whose head lacks the recorded upstream tip, and exhausted attempts escalate like any ticket. The worker's gate gets no bypass: `factory gate --upstream REF` (repeatable; the dispatcher passes the tip and the staged head, also on refresh and manager FIX) ignores only protected-path hits whose HEAD content equals the staged head's, or the tip's for a path upstream itself changed, so worker edits to protected or add-only paths, including deleting or resetting fork-only files, still need the human `factory-protected-override` label, and leak-scans the diff from the first REF, so worker-written content is scanned while upstream's is not. The merge stage keeps merging (not squashing) PRs carrying upstream ancestry. This deliberately removes 0.3.8's direct landing of the conflict-free prefix (`d77f625`, PR #117): a staged prefix reaches `main` only inside the reviewed PR, so a persistent conflict delays the whole batch rather than advancing `main` unreviewed. `sync_escalate` and the `upstream_sync` escalation code are gone; an open `upstream sync:` issue, worker- or human-owned, still parks the stage until it closes.
- Dispatcher root pinning (#181): every non-dry-run pass starts with `git fetch origin <main>` and `git checkout --detach origin/<main>` in the main checkout, and only then loads `.factory.toml` (the pin reads just `[repo].main` from the raw file, so a stale root whose config the engine rejects still picks up the fix from origin/main), so config, lessons and the dashboard theme come from the committed tip rather than whatever branch or edits the root carries. A root with tracked or untracked changes outside `.factory/` is left untouched: the pass exits 1 with a `project_escalation`/`root_dirty` dispatcher exit row and a `result` row listing the paths, and claims nothing.
- Refused `agent/<n>` push no longer strands the ticket (#244): when the remote branch gained a commit the worktree lacks (GitHub "Update branch"), the refused lease is escalated with `code="lease_refused"` — issue un-assigned, `ready-for-human`, one comment — and the worktree is kept, on both the first push and review-bounce pushes. Any other exception after the `@me` claim escalates with `code="dispatcher_error"` before re-raising, so a dispatcher crash hands the ticket back instead of leaving it assigned + `ready-for-agent` to be skipped forever.
- Ops Attention never offers Re-queue agent for `upstream sync:` issues (#169): each dashboard ticket carries `sync` (title starts with `dispatch.SYNC_TITLE`), and the workspace routes a flagged ticket to the system-upstream card with resolve-and-close guidance even when it is not the snapshot's upstream blocker. Park/resume and the `requeue_agent` refusal are unchanged; no label is added.
- Escalation-reason experiment (#163): `experiments/escalation-reasons/` hand-labels every `ready-for-human` escalation in this repository's journal as `requirement`/`eval`/`environment`/`model`/`knowledge` (62 escalations after folding re-fires, 42 tickets) and ships a deterministic `classify.py` that recovers the `code` of pre-#241 rows from their prose and agrees with the hand labels on 60/62; `REPORT.md` recommends a fixed `code → tag` grouping and two code-driven routing rules, and drops `knowledge` (3 secondary labels, 4.8%). Routing is unchanged.

Rows journaled before the fix remain in the ledger.

- `factory learn` mines lowest-scored sessions (#235): each chosen ticket's evidence replaces the 40-line failing-attempt log tail (`Working...` for OMP workers) with an excerpt of its lowest-`efficiency` `score` row's transcript (ties: lowest `compliance`, then a gate FAIL): every back-to-back repeated call, the final assistant message, then every tool call whose result mentioned `error`/`Traceback`/`FAIL` with the result's first 10 lines, at most 3,000 characters per ticket under the existing 24,000-character evidence cap (the repeated calls come first so the cap only shortens the flagged-call list).
