The PM’s contribution

Not every request
needs to become
a feature.

01Understand the problem.

Start with the person and the obstacle. Our rocm-cli example began with a request for an assistant and became a question about understanding an error.

02Choose useful work.

Build, investigate, or wait. Give the next step an owner and a review point, and start only what the team can work toward finishing.

03Check whether it helped.

Return to the developer after the change. The important result is that they can move forward—not simply that an agent produced code.

Agents can make implementation faster. The PM helps decide where that speed is worth using.

The PM’s job is not to turn every request into a feature.

It is to help the team understand the problem, choose useful work, and check whether that work helped.
