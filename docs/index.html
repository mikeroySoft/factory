control surfaces

Deterministic where it matters.

Runs on your Linux machine with the agent CLIs you choose. No hosted control plane and no Python dependencies. Model calls use your configured providers.

Isolation

Worktree per ticket

Workers implement each ticket on an isolated branch and worktree, not your main checkout.

Gate

Your gate, not ours

Any [[gate.check]] commands, exclusive lock for GPU or serial checks, and per-check timeouts.

Review

Second-model review

Blocking findings must cite an acceptance criterion, a documented rule, or a concrete defect. Required fixes stay separate from optional suggestions.

Merge

Four-way condition

Gate, reviewer, GitHub CI, and freshness. Fail-closed.

Handoff

Evidence-bound escalation

ready-for-human with the reason, log path, and handoff note.

Recovery

A bounded manager stage

Opt in to recover untouched escalations through retry, rewrite, split, route, or human handoff. Decisions are recorded before changes; invalid output stays with a human.

Human judgment

Understand. Compare. Decide.

Inbox briefings bring the question, recommendation, alternatives, and consequences together. Preview the exact action before confirming it with your rationale.

Context

Ask FM, with evidence

Ask about a task or a specific log and get cited answers. Read-only questions use server-collected evidence and are not posted to GitHub.

Learning

Make the next run better

Track attempts, review bounces, and time to merge. Distill finished-ticket evidence into repo-specific lessons you review and commit for future workers.

how a ticket moves

Evidence at every handoff.

Issues labelled ready-for-agent move through a worktree, your deterministic checks, a second model, GitHub CI, and freshness against main.

  1. 01

    Triage

    Deterministic lint rejects bodies under 80 chars or without acceptance criteria; the model then picks one of four labels. wontfix is only ever proposed.

  2. 02

    Claim

    The dispatcher re-reads the issue, assigns itself, takes a per-ticket flock, and creates .factory/wt-<n> on agent/<n>.

  3. 03

    Work

    The worker gets the issue, comments, standing instructions, a per-ticket brief, and on retries the previous gate report or reviewer findings.

  4. 04

    Gate

    Conflict markers, your [[gate.check]] list in order, then a leak-scan of added lines. Exclusive checks serialise on a host-wide lock.

  5. 05

    Review

    The reviewer sees the diff, issue, and gate report. REVISE returns to the worker; APPROVE adds factory-approved.

  6. 06

    Merge stage

    One PR per pass, requiring gate PASS, factory-approved, green GitHub checks, and a head containing the current main tip.

  7. 07

    Escalation

    Unresolved work gets ready-for-human with a reason, logs, and handoff evidence. The worktree stays for forensics. Human intervention takes precedence over automatic recovery.

  8. 08

    Manage · opt-in

    When configured, the manager revisits untouched escalations within a round limit. Factory applies a closed decision menu and records the result; unresolved cases stay with a human. The configured executable is trusted, not sandboxed.

quick start

Bring your own checks. Keep your own machine.

Linux, Python >= 3.11, git, authenticated gh with push access, and worker/reviewer CLIs. Ask FM requires authenticated OMP and sends evidence to the selected model provider.

shellquick start
cd your-repo
factory init            # .factory.toml, .gitignore, issue template, labels
$EDITOR .factory.toml   # put your real test/lint commands in [[gate.check]]
git add .factory.toml .gitignore .github/ISSUE_TEMPLATE/agent_task.md && git commit
factory doctor          # tools, auth, remotes, model endpoint
factory install --dashboard   # systemd user timer every 10 min + dashboard on :8765
factory triage

Label needs-triage issues via the local model.

factory dispatch

One stateless pass through upstream sync, merge, the optional manager stage, and eligible ticket execution.

factory gate

Run the deterministic gate in the current worktree and write a Markdown report.

factory manage

Bounded recovery for untouched escalations. Inert until [manager].command is configured.

factory stats

Ticket table: attempts, review rounds, hours to merge; --json.

factory learn

Distill lessons from finished tickets into .factory-lessons.md.

factory dashboard

Inbox decision briefings, cited Ask FM answers, and Ops telemetry. Binds to localhost by default; exposing it to a network also exposes its mutating API.

changelog

What changed.
And why.

From a ticket pipeline to an evidence-backed operation. Selected milestones below; release notes and linked decisions keep the full record.

  1. Unreleased · main only Initiative planning Not included in v0.3.0

    A shared plan above the ticket queue

    An initiative issue template and read-only factory plan list / factory plan inspect N make outcomes, owners, open decisions, and implementation links inspectable.

    • Plans live in GitHub issues, alongside the discussion and delivery evidence.
    • Status is an explicit declaration, not an inference from closed child tickets. Ownership routing and the shared dashboard are still ahead.

    The decision: one canonical plan, no second database. Reading a plan does not authorize execution; the initiative label is not yet an enforced dispatch guard. Read the collaboration contract.

  2. Latest release v0.3.0 September 8, 2026

    Recover deliberately. Review with evidence.

    • Manager recovery: opt-in, bounded decisions for untouched escalations, journaled before GitHub changes. Failed mutations are not replayed.
    • Grounded review: blockers need a criterion, rule, or concrete defect; optional suggestions no longer masquerade as required fixes.
    • Safer merges: refresh from the remote PR branch when no local branch exists, reject empty refreshes, and preserve upstream-sync ancestry.
    • Authoritative runtime evidence: execution, child-process, wait, and handoff records; a read-only runtime projection; human-touch and per-label pass metrics.

    The decision: let the model recommend, let code constrain the action, and keep the evidence. A passing gate is not permission to ignore a real defect. Read the review-contract decision.

  3. Foundation The original pipeline Before tagged releases

    Start with a ticket. End with evidence.

    Label-driven triage, one worktree per ticket, repo-defined gates, second-model review, and fail-closed merging established the core loop. The dashboard, handoff notes, and learning loop made that work inspectable.

    • Use the agent CLIs and deterministic checks the repository already has.
    • Keep operational state in GitHub and local event files, with a re-runnable dispatcher rather than a hosted control plane.

    The decision: automate the implementation, not the definition of success. Your acceptance criteria and checks remain the contract.

In progress · staged rollout

Shared plans. The right human.

Shape major changes above the issue queue, route decisions to the responsible person, and bind implementation to an approved plan revision. The read-only initiative reader is on main; routing is under revision. Handoffs and the shared dashboard remain held for human-reviewed rollout.

Why: separate outcome ownership, decision ownership, and the runner’s execution claim. One runner per repo; humans keep their own GitHub identities. Completion requires a real two-human workflow, not just merged tickets.

Collaboration programme #52 · Acceptance checkpoint

In progress · not yet merged

Keep open PRs moving

Extend manager oversight to every open agent PR: understand pending CI, stale branches, review loops, and conflicts; choose bounded recovery or a terminal human handoff. Implementation is under review.

Why: opening a PR is not finishing a ticket. Recovery needs an accountable next step without overriding human intervention.

PR frontier #15

Planned · not started

Review contributor PRs, too

An opt-in review lane for PRs outside Factory’s own worker flow: publish cited GitHub reviews, re-review changed heads, track CI readiness, and surface a human review queue.

The boundary: review contributor work without pushing to its branch or merging it. This lane is scoped in the backlog, not available today.

Review intake #5 · Dashboard queue #9

Research · no ship date

Measure what review misses

Calibrate review against known defects, not just whether a model agrees. The required/optional contract has shipped; reliable defect detection remains an open problem.

The decision: do not force a second reviewer to disagree. Explore evidence-seeking review instead. Self-reported coverage is not proof, and the small calibration experiment is not an accuracy benchmark.
